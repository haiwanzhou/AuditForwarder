========================================================================
  AuditForwarder 实验环境 · 启动说明
  基于新采集器与合谋检测模块的跨操作员合谋实验
========================================================================

这份文件说明：每个启动文件是干什么的、账号密码是多少、
以及双击之后没反应/显示离线的时候怎么处理。

  ★ 最重要的一条
    这些 .bat 文件必须留在现在这个位置（启动器文件夹里），
    不要单独把它们复制到桌面上，也不要改名成别的。
    它们靠"上一级目录"去找程序，一旦挪走就找不到。

    换电脑、拷给同学的时候，要拷的是整个 AuditForwarder 文件夹，
    不是只拷启动器这一个文件夹。


------------------------------------------------------------------------
一、这套系统由四个部分组成
------------------------------------------------------------------------

  1. 监管服务端
     作用：接收所有操作日志，按规则判断是不是合谋，出告警。
     地址：http://127.0.0.1:8443/ui
     端口：8443

  2. 图书管理系统
     作用：被监控的业务系统。两个管理员在它上面做操作。
     地址：http://127.0.0.1:18080/
     端口：18080

  3. 采集客户端 A（管理员甲）
     作用：记录浏览器发出的每一个请求，转给服务端。
     代理端口：8888

  4. 采集客户端 B（管理员乙）
     作用：模拟第二台管理员电脑，单人演示时可以不启动。
     代理端口：8889

  简单理解：
     图书系统是「案发现场」，采集客户端是「安装在电脑上的记录器」，
     监管服务端是「看监控的后台」。


------------------------------------------------------------------------
二、怎么启动
------------------------------------------------------------------------

  每个启动文件都会自己把网页打开，不用再另外点「7-打开网页.bat」。

  最省事的办法：

     双击「5-一键全部启动.bat」

  它会按顺序启动四个组件，最后把浏览器页面一起打开，
  再把四个组件的在线状态列出来。

  启动完之后，屏幕上会多出 4 个黑窗口。
  每个黑窗口就是一个组件，关掉哪个窗口就停掉哪个组件。


  想单独启动某一部分，就双击对应的文件（箭头后面是它自动打开的网页）：

     1-启动服务端.bat        监管服务端（8443）   -> 监管界面
     2-启动图书管理系统.bat   图书系统（18080）    -> 图书业务界面
     3-启动采集客户端A.bat    采集端 A（8888）     -> 实验操作台
     4-启动采集客户端B.bat    采集端 B（8889）     -> 实验操作台（第二个人）
     5-一键全部启动.bat      四个一起启动        -> 全部页面
     6-一键全部停止.bat      把四个全部关掉
     7-打开网页.bat          只补开网页，不启动程序
     8-清空告警数据.bat      把告警清回 0         -> 监管界面
     9-状态检查.bat          看看四个组件现在是不是都在线


  正确的启动顺序（如果分开启动的话）：

     先 1（服务端）-> 再 2（图书系统）-> 再 3 和 4（采集端）

     顺序错了也能用，但采集端连不上服务端会一直重试，
     那段时间的日志可能丢，所以要按顺序来。

  小提示：
     网页没打开、或者不小心关掉了，再双击一次那个 .bat 就行。
     程序发现端口上已经有一个在跑，只会补开网页，不会再起一个新进程。

    用户名        密码        角色        用途

    admin         admin123    管理员      演示主要用这个
    admin2        admin123    管理员      双人实验里的第二个人
    admin3        admin123    管理员      R-005 规则需要三个管理员
    librarian1    lib123      馆员        权限比管理员低一级
    librarian2    lib123      馆员        备用
    member1       member123   读者        普通用户，只能借书还书

    说明：
      管理员 可以改系统配置、重启服务、清日志、管备份、管用户
      馆员   可以加书、借还书，不能碰系统配置
      读者   只能查书、借书


  【监管端】  http://127.0.0.1:8443/ui

    用户名        密码
    ----------    --------
    admin         admin123


  【采集客户端】不需要登录

    采集端的身份写在配置文件里：

      客户端 A  config\client_lab.yaml
                主机标识 lab-pc      操作员 admin    代理端口 8888

      客户端 B  config\client_lab_peer.yaml
                主机标识 lab-pc2     操作员 admin2   代理端口 8889

    注意：
      配置里的操作员只是「兜底」。实际上是谁在操作，
      取决于浏览器里登录的是哪个账号 —— 登录成功时服务器会下发一个
      身份 Cookie（名字叫 af_operator），采集端读的是它，不是配置文件。
      所以只要两个人各自登录不同账号，证据链上就能分出「谁做的」。

    两台机器部署时，两个配置文件里的 host_id 必须不一样，
    数据目录也必须不一样（data\client 和 data\client2），
    否则两个人的操作会被当成一个人，合谋永远判不出来。

四、网页窗口是怎么来的、要注意什么
------------------------------------------------------------------------

  正常用的时候不用管这一章：1、2、3、4、5、8 双击完会自动跳网页。

  但有一条必须记住：
    要操作业务（加书、备份、点剧本按钮），必须在「走代理的那个窗口」里做。
    你自己平时用的浏览器不走代理，页面一样能点、数据一样会变，
    但监管端数字永远不动 —— 这不是系统坏了，是流量没经过记录器。

  怎么分辨哪个窗口是走代理的：
    它跟你平时的浏览器不是同一个（用的是另一套配置目录），
    没有书签、没登录任何网站、地址栏也没有你的历史记录，一眼就能认出来。

  各页面分别落在哪个窗口：

    走 8888 代理（会被采集，操作要用这个）
        http://127.0.0.1:18080/console   实验操作台，剧本按钮
        http://127.0.0.1:18080/app       图书业务界面，正常加书借书
        http://127.0.0.1:18080/admin     系统运维界面，备份/配置/日志

    走 8889 代理（模拟第二个人，对应客户端 B）
        http://127.0.0.1:18080/console   同上，但身份记在第二个人名下

    不走代理（只看结果，不在上面做业务）
        http://127.0.0.1:8443/ui         监管端，看告警和证据链

  2-启动图书管理系统 有一个特殊情况：
    如果当时采集端 A（8888）还没启动，它只能用普通浏览器打开，
    那个页面上的操作不会被采集，窗口里会写一行提示。
    先启动 3，再回来双击一次 2，就会换成走代理的窗口。

  想一次性补开全部页面，仍然可以双击「7-打开网页.bat」。


  在运维界面里换人／同时扮多个人

    打开 http://127.0.0.1:18080/admin ，点右上角「切换用户」按钮，
    或者点顶部最后一个标签「切换用户」：

      - 六个账号排成卡片，点一下就直接换成那个账号（密码已内置）
      - 当前账号会高亮显示 ✓ 当前，右上角的名字也会跟着变
      - 想换的账号不在卡片里，用下面的「用其他账号登录」自己输
      - 「退出登录」会连身份 Cookie 一起清掉

    做「甲 乙 丙」这种三个人配合的实验，请用三个标签页：

      开三个 /admin 标签页：
        第 1 个点 admin   第 2 个点 admin2   第 3 个点 admin3
      然后按顺序做：
        页1 生成密钥  →  页2 分发  →  页3 清空密钥审计

      每个标签页只记住自己是谁，互不干扰，采集端会记成三个人。
      右上角那个名字，就是「这个标签页现在是谁」——点操作按钮前
      看一眼它，就不会记错人。

      补充：只要有 2 个以上不同账号分担这三步，就会被判，
        不一定非要三个人各做一步。甲做前两步、丙做最后一步，
        与甲/乙/丙各做一步，走的是同一条判定逻辑。
        2 人起步 75 分（中风险）；3 人及以上每人再 +5 分（高风险）。
        反过来，同一个人把三步全做完不判 —— 那不是合谋，是单人越权，
        属于另一类威胁（单点滥用），由别的规则管。

      时间不设死限制（链式滑动匹配）：
        三步不要求挤在同一小段时间里。甲早上建密钥、乙下午分发、
        丙晚上清审计，跨度 12 小时照样会被拼成一条链判成合谋。
        系统不再按「15 分钟一个窗口」把事件硬切开，而是以最新一步为
        锚点向前回溯，最多回溯 7 天（链总跨度，可配）。
        跨度越长，说明证据关联越弱，所以会温和扣分（每超 1 小时扣 1 分、
        最多扣 15 分），但扣分不等于放过——依然是中风险/高风险。
        想靠「隔足够久」来绕过，是绕不过去的。

    为什么以前会失败（这条最重要）：

      登录 Cookie 是整个浏览器共用的一份。你在任何一个标签页换了人，
      所有标签页的 Cookie 都跟着变；而每个页面打开时读到的登录令牌
      还留在内存里，于是出现「用着甲的令牌、身份却是乙」。
      结果三个标签页的动作全记在最后切换的那个人名下——人数凑不到 3，
      规则不成立，一条告警都不会出，而且不会报任何错，
      看起来就像「检测失灵」。

      判断有没有踩坑的两个办法：
        1) 去监管端看告警里的「操作员」。只有一个名字，就是没分开。
        2) 看密钥列表的「创建人」，和采集到的操作员不是同一个人。

    要演示「两个人、两台电脑」，用 8888 和 8889 两个窗口各登一个账号，
    那是两条独立的采集源，最接近真实场景。

五、双击之后没反应、或者显示离线，怎么办
------------------------------------------------------------------------

  【情况 1】双击后黑窗口一闪就没了

    现在每个启动文件在失败时都会停住并显示原因，不会再一闪而过。
    如果还是闪退，说明是 Windows 拦住了：

      右键那个 .bat 文件 -> 属性 -> 如果在最下面看到
      「此文件来自其他计算机」-> 勾上「解除锁定」-> 确定

    如果整个文件夹是从别的电脑拷过来的，建议先全部解除锁定。


  【情况 2】监管界面里主机显示「离线」

    按这个顺序查：

      1. 双击「9-状态检查.bat」，看哪个是离线
      2. 服务端离线    -> 双击「1-启动服务端.bat」
      3. 采集端离线    -> 双击「3-启动采集客户端A.bat」
      4. 都显示在线，主机还是离线
                       -> 说明客户端的 host_id 跟服务端登记的对不上，
                          或者客户端的服务端地址写了别的 IP
      5. 客户端 B 一直离线
                       -> 它的配置文件里服务端地址可能是旧的局域网 IP。
                          单机演示时把 config\client_lab_peer.yaml 里的
                          10.4.55.6 改成 127.0.0.1


  【情况 3】提示「端口已被占用」

    说明上次的进程没有正常退出，还占着端口。

      双击「6-一键全部停止.bat」
      然后再双击「1-启动服务端.bat」

    启动文件本身也会检测这种情况：
    如果发现端口被占但服务是好的，会直接告诉你「本来就在运行」；
    如果占着端口却连不上，会自动结束残留进程再重新启动。


  【情况 4】页面上点了按钮，监管端数字不涨

    1. 检查浏览器是不是启动文件自动打开的那个「走代理」窗口
       （没有书签、没登录过网站的那一个）
    2. 双击「9-状态检查.bat」，确认采集端 8888 在线
    3. 如果这一步是两个人做的，确认两台机器都登了不同账号
    4. 看一下时间：告警不再按「15 分钟一个窗口」硬切分，跨窗口、
       隔几个小时、甚至隔天的操作也会被拼成一条链判定（最长回溯 7 天），
       只是跨度越长分数越低一点。所以「隔太久没判出来」一般是别的原因：
       ① 这步不是同一个剧本的三步；② 两个人实际记成了同一个人；
       ③ 隔了超过 7 天才做，超出回溯范围。前两种是主因。


  【情况 5】页面显示 404 或者样式错乱

    在那个窗口按一次 Ctrl + F5（强制刷新），
    把浏览器缓存的旧页面清掉。

六、演示的完整流程（一个人也能走完）
------------------------------------------------------------------------

  1. 双击「5-一键全部启动.bat」，等它把四个组件拉起来（页面会自动打开）

  2. 双击「8-清空告警数据.bat」，输入 Y 回车
     （让告警从 0 开始，这样后面数字每跳一次都能看见）

  3. 在操作台窗口里，左边选 admin，密码 admin123，点「登录 / 切换」

  4. 点右边 R-003「配置篡改链路」的三步按钮：
        第 1 步  修改系统配置
        第 2 步  重启服务
        第 3 步  清空系统日志

  5. 看监管端：高风险应该跳到 1，点进去能看见证据链

  6. 想证明「正常业务不会误报」：
        打开 /app 那个窗口，随便加一本书、借一本书
        监管端数字不动 —— 这就是对照组


  两个人做的版本：

     甲（这台电脑）  登录 admin，做第 1、3 步
     乙（另一台）    登录 admin2，做第 2 步

     结果里会显示两个不同的操作员、两台不同的主机，
     这就是合谋和单人操作的区别。

七、文件放在哪
------------------------------------------------------------------------

  启动器文件夹（就是本文件所在的文件夹）
      全部双击用的 .bat 文件 + 这份说明

  ..\build\Release\
      编译好的程序（服务端、采集端）

  ..\config\
      配置文件。改了配置要重新启动对应的组件才生效

  ..\data\
      运行数据。server 是服务端的，client / client2 是两个采集端的

  ..\data\server\server.log
      服务端日志。服务端起不来的时候，看这个文件最后几十行

  ..\lab\book_system\
      图书管理系统源码和数据库

  ..\docs\EXPERIMENT_MANUAL_2P.md
      双人实验的详细手册（拓扑图、逐步操作、答辩问题）


========================================================================
  最后提醒一句
========================================================================

  四个组件各占一个黑窗口，那些窗口不是垃圾，是正在运行的程序。
  演示的时候把它们排开放在一起，看起来就是「两台管理员机器 +
  一台监管机器」的样子，讲的时候也方便指。

  演示结束，双击「6-一键全部停止.bat」全部关掉即可。
