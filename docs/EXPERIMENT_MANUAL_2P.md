# 双人合谋实验 · 局域网操作手册

> 适用场景：**两台管理员电脑 + 一台监管端**，两个真人各自登录一个管理员账号，
> 分开做几件单独看都合规的事，由监管端把它们串成一次合谋攻击。
>
> 本手册是 `EXPERIMENT_MANUAL.md`（单人版）的补充，不替代它：
> 单人版讲原理和五个剧本，这一份只讲**两个人怎么分工、点哪个按钮、看到什么算成功**。

对应代码状态：`main` 分支，含
「事件按发生时间插入」「远程队列分批发送」「控制台跨机步骤自解析」三处修复。

---

## 0. 先把三台机器说清楚

只有两个人在操作，但机器有三台。第三台（监管端）**不需要人操作**，
起来之后放着就行，谁都可以去看结果。

| 代号 | 谁在用 | 跑什么 | 监听端口 | 本手册里叫它 |
|---|---|---|---|---|
| **M1** | 同学 A | 采集客户端 + 浏览器操作台 | 127.0.0.1:8888 | 管理员 A 的电脑 |
| **M2** | 同学 B | 采集客户端 + 浏览器操作台 | 127.0.0.1:8888 | 管理员 B 的电脑 |
| **M3** | 没人（放着） | 监管服务端 + 图书管理系统 | 0.0.0.0:8443 / 0.0.0.0:18080 | 监管端 |

```
        ┌──────────────┐         ┌──────────────┐
        │  M1  同学 A   │         │  M2  同学 B   │
        │              │         │              │
        │ 浏览器 ──┐    │         │ 浏览器 ──┐    │
        │         ▼    │         │         ▼    │
        │ 采集器 8888   │         │ 采集器 8888   │
        └──────┬───────┘         └───────┬──────┘
               │  日志(host_id=lab-pc)   │  日志(host_id=lab-pc2)
               └───────────┬─────────────┘
                           ▼
                 ┌──────────────────────┐
                 │  M3  监管端           │
                 │  :8443 服务端         │
                 │  :18080 图书管理系统   │
                 │  按「资产组+时间窗」   │
                 │  聚合两台的日志        │
                 └──────────────────────┘
                           ▲
                    两人都可以用浏览器
                    看 http://<M3>:8443/ui#collusion
```

**数据流的关键**：M1 / M2 的浏览器不是直接连 M3 的 18080，
而是先经过自己机器上的 8888 代理，采集器看到请求、解析出「谁在操作」，
再异步上报给 M3。所以：

> 浏览器**必须走代理**，否则接口全都返回 200，但服务端一条日志都收不到。

## 1. 开工前准备（做一次，约 20 分钟）

### 1.1 把这三个地址填下来

后面所有命令里的 `<M3>` 都指这张表里的 IP。

| 项 | 填什么 | 怎么查 |
|---|---|---|
| M1 局域网 IP | `____________` | `ipconfig`，看「IPv4 地址」 |
| M2 局域网 IP | `____________` | 同上 |
| **M3 局域网 IP** | `____________` | 同上，**这个最重要** |
| 三台是否同一网段 | 是 / 否 | 前三段相同（如 192.168.1.x）就算同网段 |

> 不同网段（比如一个连 WiFi 一个插网线）也能通，但要确认路由可达：
> 在 M1 上 `ping <M3>` 必须通。ping 不通后面全白做。

### 1.2 把目录复制到 M2

M2 需要一份完整程序。在 M3 上（或从 M1）打包：

1. 在要打包的那台机器上先停掉程序（`lab\stop_lab.bat`），否则 exe 被占用、拷不出来。
2. 把整个 `AuditForwarder` 文件夹压成 zip，拷给 M2 解压。
3. **在 M2 上删掉 `data\server` 整个目录**（那是 M3 的判定数据，带过去只会让人困惑）。
4. **`data` 这个文件夹本身要留着**：`_peer.bat` 要往 `data\lab_client2.log` 写日志，
   目录不存在的话客户端一闪就退，看不到任何报错。

`build` 58 MB、`lab` 427 KB，`data\server` 有 100 MB 左右，所以打包前删掉它，zip 会小很多。

### 1.3 改 M1 的配置

文件：`config\client_lab.yaml`。只需改 **3 行**（把示例 IP 换成你的 `<M3>`）：

```yaml
transport:
  servers:
    - "http://<M3>:8443/ingest?agent=lab-pc"      # ← 原来是 127.0.0.1

remote:
  servers:
    - "http://<M3>:8443"                          # ← 原来是 127.0.0.1
  host_id: "lab-pc"                               # ← 保持不动，M1 的身份

collectors:
  http_proxy:
    listen_port: 8888                             # ← 保持不动
    target_hosts: ["127.0.0.1", "localhost", "<M3>"]   # ← 加上 <M3>
```

### 1.4 改 M2 的配置

文件：`config\client_lab_peer.yaml`。改 **4 行**：

```yaml
transport:
  servers:
    - "http://<M3>:8443/ingest?agent=lab-pc2"     # ← 原来是 10.4.55.6

remote:
  servers:
    - "http://<M3>:8443"                          # ← 原来是 10.4.55.6
  host_id: "lab-pc2"                              # ← 必须和 M1 不一样！

collectors:
  http_proxy:
    listen_port: 8888                             # ← 原来是 8889，改成 8888
    target_hosts: ["127.0.0.1", "localhost", "<M3>"]   # ← 加上 <M3>
```

两个容易犯的错：

- **`host_id` 两台不能相同**。它是证据链里「这条操作来自哪台机器」的唯一依据。
  相同的话两份日志会写进同一个目录，合并后看起来像一个人在两台机器上分身。
- **`listen_port` 两台都是 8888**。8889 只是「同一台电脑上同时跑两个实例做预演」时用的，
  真分两台机器就不需要了，各自 8888 互不干扰。
- `target_hosts` 必须写成 `[...]` 这种**行内数组**。写成每行一个 `- 值` 的块序列，
  本项目自带的 YAML 解析器会静默丢成空列表，而空列表的含义是「采集所有主机」——
  现象是能采到，但整机流量把证据淹了。

### 1.5 在 M3 上放行两个端口

以管理员身份打开 PowerShell：

```powershell
netsh advfirewall firewall add rule name="AF-8443" dir=in action=allow protocol=TCP localport=8443
netsh advfirewall firewall add rule name="AF-18080" dir=in action=allow protocol=TCP localport=18080
```

放行之后**在 M1 和 M2 上各验一次**（这一步不过，后面全是白忙）：

```bat
curl -o NUL -w "server=%{http_code}\n" http://<M3>:8443/collusion/overview
curl -o NUL -w "book=%{http_code}\n"   http://<M3>:18080/
```

两个都要返回 `200`。第 1 个返回 `000` = 服务端没起或防火墙没放行；
第 2 个返回 `000` = 图书系统没起。

### 1.6 对表

两台机器的时钟差不能超过一两分钟——聚合用的是事件里记的发生时间
（`client_ts`），差太多会掉进不同的 15 分钟窗口。

Windows：设置 → 时间和语言 → 日期和时间 → **立即同步**。
或者命令行 `w32tm /resync`（管理员）。

## 2. 启动（顺序不能乱：先 M3）

### 2.1 M3：服务端 + 图书系统

```bat
cd /d <项目目录>
lab\_srv.bat        :: 服务端 0.0.0.0:8443
lab\_book.bat       :: 图书系统 0.0.0.0:18080
```

两个都是**黑窗口，不要关**。确认 M3 本机能打开
`http://127.0.0.1:8443/ui` 和 `http://127.0.0.1:18080/`。

### 2.2 M1：采集客户端

```bat
lab\_client.bat
```

黑窗口里应该能看到连接成功的日志。**不要关这个窗口**。

### 2.3 M2：采集客户端

```bat
lab\_peer.bat
```

### 2.4 三处自检（30 秒）

| 检查 | 在哪做 | 通过的样子 |
|---|---|---|
| 采集器在听 | M1、M2 各跑 `netstat -ano \| findstr :8888` | 有一行 `LISTENING` |
| 两台都在上报 | **M3 上** `dir data\server\operation_logs` | 出现 `lab-pc` 和 `lab-pc2` 两个目录 |
| 真的采到东西 | **M3 上** `dir data\server\operation_logs\lab-pc2` | `http_proxy.jsonl` 存在，且大小不是 0 |

> 如果没有 `lab-pc2`：M2 的采集器没连上服务端，看 `data\lab_client2.log`。
> 八成是 `transport.servers` / `remote.servers` 还写着旧 IP。
>
> 别去看 `data\server\hosts.json`——那个文件不是 UTF-8，记事本打开是乱码，
> 容易误判成「坏掉了」。检查主机只认上面这两个目录。

### 2.5 打开浏览器

**在 M1 上**：

```bat
lab\open_lan.bat <M3>
```

**在 M2 上**：

```bat
lab\open_lan.bat <M3>
```

这个脚本会用一个**独立的浏览器配置**（`%LOCALAPPDATA%\af-lab-browser`）打开
`http://<M3>:18080/console`，并且把代理显式设成 `127.0.0.1:8888`。
用你自己的日常浏览器窗口打开是不行的——代理没开，什么都采不到。

它同时会弹出监管控制台 `http://<M3>:8443/ui#collusion`（这个**不走代理**，
看着告警不应产生日志）。

> 页面要不要刷新？第一次登录后如果顶部状态栏显示「暂无高风险事件」，
> 说明 M3 可达、采集器正常。如果显示红字「监管端（8443）不可达」，先解决这个。

## 3. 每次实验开始前（2 分钟，别省）

### 3.1 清空上一次的告警

**在 M3 上**：

```bat
set PY=%USERPROFILE%\.workbuddy\binaries\python\versions\3.13.12\python.exe
%PY% lab\clear_alerts.py --status     :: 先看一眼当前有多少
%PY% lab\clear_alerts.py              :: 清空（会重启服务端，不动客户端）
```

清完 `--status` 应该是 `HIGH 0 / MID 0 / LOW 0 / 待复核 0 / 画像 0`。

> **不要用 `--full`**。`--full` 会把客户端一起重启，而客户端刚起来的几分钟里
> 带请求体的 POST/PUT 会被静默丢弃（GET 不受影响），而本实验每一步几乎都是
> POST/PUT/DELETE。默认模式只重启服务端，客户端一直活着，不踩这个坑。

### 3.2 看一眼时钟，避开窗口边界

聚合窗口是**固定的 15 分钟**，切分点是 `:00 / :15 / :30 / :45`。
一次三步的合谋如果横跨了边界，前两步落在一个窗口、第三步落在下一个窗口，
两个窗口各缺几步，就永远凑不齐。

**规则很简单**：

- 现在是 `:03` → 可以马上开始。
- 现在是 `:13` → **等 2 分钟**，过了 `:15` 再开始。
- 一句话：**别在 XX:13 / XX:28 / XX:43 / XX:58 之后开始**。

想看得精确一点，在 M3 上跑：

```bat
%PY% -c "import time;w=900000;e=int(time.time()*1000)%w;print('距窗口边界还有 %d 分 %02d 秒'%((w-e)//60000,(w-e)%60000//1000))"
```

少于 120 秒就先等一等。

### 3.3 两台都回到「干净页面」

- 在 M1 的 console 页面点「立即刷新」，确认高风险是 0。
- 在 M2 的 console 页面做同样的确认。
- 两个页面都停在自己该登录的账号上（下一步会说谁登谁）。

## 4. 分工：谁登哪个号

**固定分工，整场不要换**：

| 人 | 机器 | 登录账号 | 密码 |
|---|---|---|---|
| 同学 A | M1 | `admin` | `admin123` |
| 同学 B | M2 | `admin2` | `admin123` |

> 为什么必须一人一个账号：日志里的操作员身份是从请求的
> `Authorization: Bearer <token>` 里解出来的。两个人用同一个账号，
> 服务端看到的就是「同一个人」，`distinct_op_count` 永远是 1，
> 合谋判定会直接跳过——不管你们做了多少步。

操作步骤（两台一样）：

1. 左侧「切换操作员」→ 下拉选自己的账号（A 选 `admin`，B 选 `admin2`）。
2. 点「登录 / 切换」。
3. 看到右上角徽章从「未登录」变成自己的账号名，下面出现绿字
   「已切换为 xxx，接下来你的操作都会被记在它名下」。
4. 右侧剧本列表里，**属于自己账号的步骤旁边那个小标签会变绿**
   （A 看到 `admin` 高亮，B 看到 `admin2` 高亮）。

> 点别人的步骤会弹一个确认框。**看到确认框就说明点错了人**，点取消。

## 5. 正式实验（四个场景，约 15 分钟）

每个场景内部，**每点完一步等 3 秒**再点下一步。这个等待是给采集器
攒批 + 上报用的；连得太快也能测出来（事件按发生时间排序），但等 3 秒
最稳，而且方便你观察数字变化。

### 场景 0 · 对照组：正常业务不该告警（1 分钟）

先证明「系统不是见谁咬谁」。

| 步 | 谁 | 在哪 | 点哪里 | 预期 |
|---|---|---|---|---|
| 1 | A | M1 | 最下面「对照 · 正常业务：删一本书」→ 第 1 步「删除列表里的第一本书」→ 执行 | 行变绿，HTTP 200 |

**预期结果**：顶部「高风险」数字**不动**，还是 0。
这一步的动作被归一化成 `delete.book`，而 R-001 要的是 `delete.backup`，
两者不会混淆。

> 如果这里就冒出一条 HIGH，说明规则文件被改过或动作归一化失效，
> 先停下来查，别往下做。

---

### 场景 1 · R-003 配置篡改链路（主力演示，2 分钟）

**为什么选它**：路径全是固定地址、不依赖上一步的返回值，两个人各点各的，
最短、最稳、最不容易出错。

| 步 | 谁 | 在哪 | 点哪里 | 归一化动作 |
|---|---|---|---|---|
| 1 | **A** | M1 | R-003 卡片 → 第 1 步「修改系统配置（留存改 3650 天）」 | `update.config` |
| 2 | **B** | M2 | R-003 卡片 → 第 2 步「重启应用服务」 | `restart.service` |
| 3 | **A** | M1 | R-003 卡片 → 第 3 步「清除系统日志」 | `clear.logs` |

**预期结果**（点完第 3 步后 2~6 秒）：

- M1 和 M2 的顶部状态栏：**高风险 0 → 1**，旁边出现绿色「新增 +1」，
  右侧写出「最新高风险：**R-003 配置篡改链路** · 85~100 分 · admin, admin2」。
- M3 的监管控制台多出一条 HIGH。

**这一步说明了什么**：

| 单独看 | 合起来看 |
|---|---|
| A 改配置：admin 本来就有改配置的权限 | 日志留存被拉到 3650 天 |
| B 重启服务：正常运维动作 | 让新配置立刻生效 |
| A 清日志：日常清理 | **痕迹没了，改过什么无从回溯** |

---

### 场景 2 · R-001 备份销毁合谋（3 分钟）

这个剧本有「准备素材」的步骤，必须先在 A 的机器上做掉，
否则 B 那台点「卸载数据卷」会报 404（卷根本还没挂上）。

**2-1 准备（A 一个人做，这三步不进任何规则）**

| 步 | 谁 | 点哪里 | 说明 |
|---|---|---|---|
| 1 | A | R-001 第 1 步「把数据卷挂回来（准备素材）」 | `mount.volume`，不在规则序列里 |
| 2 | A | R-001 第 2 步「造一个备份（准备素材）」 | `create.backup` |
| 3 | A | R-001 第 3 步「造一个快照（准备素材）」 | `create.snapshot` |

三步都变绿即可，此时**不应该有告警**（准备动作不在攻击序列里）。

**2-2 攻击（两人接力）**

| 步 | 谁 | 在哪 | 点哪里 | 归一化动作 |
|---|---|---|---|---|
| 4 | **A** | M1 | R-001 第 4 步「删掉刚造的备份」 | `delete.backup` |
| 5 | **B** | M2 | R-001 第 5 步「卸载数据卷」 | `unmount.volume` |
| 6 | **A** | M1 | R-001 第 6 步「删掉刚造的快照」 | `delete.snapshot` |

**预期结果**：高风险 +1，`R-001 备份销毁合谋`，85~100 分，
操作员 `admin, admin2`。

> 第 5 步和第 6 步会自己先查一次目标对象再执行（卷查「当前已挂载的」，
> 快照查「最新的那个」），所以 B 那台不需要知道 A 那边造了什么名字。
> 万一卷已经被卸过了会直接报「找不到已挂载的卷」，重新点一次第 1 步挂回来即可。

### 场景 3 · R-004 数据批量外泄（2 分钟）

| 步 | 谁 | 在哪 | 点哪里 | 归一化动作 |
|---|---|---|---|---|
| 1 | **A** | M1 | R-004 第 1 步「给 member1 加导出权限」 | `grant.user` |
| 2 | **B** | M2 | R-004 第 2 步「导出全部图书数据」 | `export.book` |
| 3 | **B** | M2 | R-004 第 3 步「清除图书审计记录」 | `clear.book_audit` |

**预期结果**：高风险 +1，`R-004 数据批量外泄`，82~100 分。

> 第 3 步由 B 做，是因为这条规则只要求 **≥2 个操作员**（`min_operator_cnt: 2`），
> A 做第 1 步、B 做第 2、3 步就已经满足。
> 如果想让分工更像「三个人接力」，可以让 A 在 M1 上把账号切成 `admin3` 再做第 3 步
> ——但这样同一个页面上就会混两个身份，报告里读起来反而乱，**建议就用 B**。

### 场景 4 · 负样本：一个人把整套做完（强烈建议做）

这是最有说服力的一步，用来证明「合谋」不是随口说的词。

1. 先清空：M3 上 `%PY% lab\clear_alerts.py`。
2. **只让 A 一个人**，在 M1 上把 R-003 的三步全部点完（admin 一个人做三步）。
3. B 什么都不做。

**预期结果**：**没有任何 HIGH**。

> 可能出现 LOW 或 MID（窗口内动作可疑），但不会升级成 HIGH。
> 原因：聚合入口先看这个窗口里出现了几个不同操作员，
> 少于 2 个直接跳过。这就是「合谋」的定义边界。
>
> 做完这一步记得再清一次基线，否则后面对比时容易看花眼。

---

### 可选 · R-002 / R-005 需要三个操作员

这两条规则的 `min_operator_cnt` 是 **3**，两个人正常做凑不齐。
想演示的话，让其中一个人在同一个页面上多切一次账号（比如 A 做完 `admin`
再切成 `admin3` 做最后一步）。因为身份是从每次请求的 token 里解析的，
同一台机器切换账号**是有效的**，不像以前那样会把 Cookie 覆盖掉。

但这两个剧本的价值不如 R-001/R-003/R-004，**时间紧就跳过**。

## 6. 结果怎么读（这一步决定实验报告的质量）

### 6.1 三个观察点

| 看什么 | 在哪 | 用途 |
|---|---|---|
| 顶部实时告警条 | M1 / M2 的 console 页面 | 现场最快：数字跳 + 「新增 +N」+ 命中的规则名 |
| 合谋协同页 | M3 上 `http://127.0.0.1:8443/ui#collusion` | 看列表、点开一条看证据链 |
| 危害定级报告 | `http://127.0.0.1:8443/collusion/incident-report` | Markdown 全文，可直接贴进实验报告 |

命令行也可以：

```bat
curl http://127.0.0.1:8443/collusion/overview
curl "http://127.0.0.1:8443/collusion/events?level=HIGH"
```

### 6.2 一条合格告警必须同时满足这五条

| 判据 | 合格的样子 | 不合格说明什么 |
|---|---|---|
| 等级 | `risk_level = HIGH` | MID 说明基础分不够或画像分为 0 |
| 操作员 | `operators` 里**至少两个不同的人** | 只有一个人 = 两人登了同一个账号 |
| 主机 | 证据时间线里同时出现 **`lab-pc` 和 `lab-pc2`** | 只有一台 = 两台机器的 `host_id` 写重了 |
| 对象（以 R-003 为例） | 三步的「对象」列分别是 `/api/system/config`、`/api/system/service/restart`、`/api/system/logs/clear` | 出现 `/__MISSING_xxx__` = 页面记的目标丢了；路径完全不相干 = 点错剧本 |
| 时间 | 三步的 `ts` 落在同一个 15 分钟窗口内 | 跨了边界 = 清空重做 |

打开告警详情，证据链长这样（下面是 R-001 的**真实输出**，不是示意）：

```
时间                  操作员   主机     动作            对象
08:11:26Z  admin    lab-pc   network/delete  /api/backup/backup_20261024_161126.db
08:11:26Z  admin2   lab-pc2  network/write   /api/storage/volume/1/unmount
08:11:26Z  admin    lab-pc   network/delete  /api/snapshot/snapshot_20261024_161126.snap
                    ↑ 两台机器、两个操作员，逐行可核对，这就是"证据链"
```

两个必须知道的地方，否则会以为哪里出错了：

- **「动作」列是 HTTP 语义**（`network/read` / `network/write` / `network/delete`），
  不是规则里用的归一化名（`delete.backup` 这种）。判定确实是按归一化动作做的，
  但页面展示的是请求语义。想知道某条日志归一化成了什么，去原文里看：

  ```bat
  findstr /c:"action_norm" data\server\operation_logs\lab-pc2\http_proxy.jsonl
  ```

- **时间线是「这个资产组 + 这个窗口」内的全部操作**，不只那三步。
  它会包含你做的准备动作（挂卷、造备份、造快照），也会包含控制台
  自己查列表的几条 GET（`network/read`）。
  写报告时按「对象」列挑出上面那三行即可，其余保留反而能说明上下文完整。


### 6.3 分是怎么来的

| 组成 | 上限 | 说明 |
|---|---|---|
| 规则基础分 | 85 / 82 / 80 | R-001=85、R-003=85、R-004=82、R-002/R-005=85 |
| 画像分 | 25 | 陌生协作 +12、跨域 +6/人 |
| 判定线 | `score_high = 80` | ≥80 出 HIGH，≥40 出 MID |

刚清空过画像时，规则分是唯一来源，所以基础分必须 ≥80，
否则命中了也只会掉成 MID——看起来就像「没检测到」。

## 7. 出问题怎么查

按「现象 → 最可能的原因」从上往下试，**一次只改一件事**。

| 现象 | 最可能的原因 | 怎么确认 / 怎么修 |
|---|---|---|
| M1/M2 顶部条红字「监管端（8443）不可达」 | M3 服务端没起，或防火墙没放行 | M3 上 `netstat -ano \| findstr :8443`；M1 上 `curl http://<M3>:8443/collusion/overview` |
| 页面能开，但点任何按钮都不涨数字 | 浏览器没走代理 | 你是不是用日常浏览器窗口开的？必须用 `open_lan.bat` |
| 同上，且 M3 的 `data\server\operation_logs` 里**没有** `lab-pc2` | M2 的采集器没连上 | 看 M2 的 `data\lab_client2.log` 有没有连接失败 |
| 有 `lab-pc2` 目录，但里面 `http_proxy.jsonl` 是空的 | `<M3>` 不在 `target_hosts` 里 | 改配置后**要重启客户端**才生效 |
| 证据链里两台机器只显示一台 | 两台 `host_id` 写成一样的了 | 改成 `lab-pc` / `lab-pc2`，重启两台客户端 |
| 只有一个操作员，永远是 LOW/MID | 两人登了同一个账号 | 看证据链第一列，必须是 `admin` 和 `admin2` |
| 点按钮报 `__MISSING_vol__` 之类 | 页面是旧缓存 | `Ctrl + F5` 强制刷新（控制台已改成每步自己查目标） |
| 卸载卷报 404 / 找不到卷 | 卷已经卸过了 | 先点 R-001 第 1 步「把数据卷挂回来」 |
| 清空后怎么点都不涨 | 客户端处在重启预热期 | 别重启客户端；`clear_alerts.py` 只重启服务端。真重启了就等 2~3 分钟 |
| 三步都做对了，但还是没有 HIGH | 跨了 15 分钟窗口边界 | 清空基线，挑 `:00` 刚过的时刻重做 |
| 图书系统 500 或列表是空的 | 之前跑过 R-005 清库 | `%PY% lab\reset_lab.py --restart`（会重建图书库） |

### 7.1 两台机器上分别该看哪个日志

| 机器 | 日志文件 | 看什么 |
|---|---|---|
| M1 | `data\lab_client.log` | 连接服务端、`operation-logs sent batches=N` |
| M2 | `data\lab_client2.log` | 同上 |
| M3 | `data\lab_server.log` | 接收批次、判定告警 |

M2 里看到 `operation-logs sent batches=...` 就说明日志真的出门了。
如果没有这行，只有心跳，那基本就是配置里服务端地址还写着旧 IP。

## 9. 老师可能会问的问题

**Q：这些操作单独看有错吗？**
没有。A 有改配置的权限，B 有重启服务的权限，单独看都在职权范围内，
业务系统也不会拦。所以靠「越权检测」是发现不了的，必须靠跨人聚合。

**Q：为什么判定为合谋，而不是两次巧合？**
三条：① 落在同一个 15 分钟窗口；② 打的是同一个资产组（`sys-config-group`）；
③ 三步动作构成一条预定义的有序序列（改配置→重启→清日志），
单独任何一步都不构成序列。三个条件同时满足才算命中。

**Q：日志被清掉了，证据从哪来？**
被清的是**图书系统自己**的日志。采集器是在网络层截流的，
日志早在客户端就进了哈希链批次、上送到监管端落盘了。
所以攻击者清掉的是业务系统的痕迹，清不掉监管端的副本——这正是本系统的设计目的。

**Q：两台机器的时间不一致会不会出错？**
会。聚合用的是事件里的发生时间。差太多会掉进不同的窗口，
或者序列判断出错。所以要求两台机器对时。

**Q：如果两台机器用同一个管理员账号呢？**
检测不到。这是本系统的一个明确边界：合谋的定义是「不同操作员之间的协同」，
同一个人做什么都不算合谋。反过来，这恰好是最有说服力的负样本（见场景 4）。

**Q：为什么必须换成「动作归一化」的名字？**
`delete.backup`（删备份）和 `delete.book`（删一本书）在原始日志里都只是
一个 DELETE 请求。不归一化就只能靠关键词匹配 `delete`，正常借还书都会误报。
归一化把「删什么」变成语义坐标，规则才能精确表达「删备份 + 卸卷 + 删快照」。
